## 2026-08-11 - Custom Interactive Element Accessibility
**Learning:** In static, single-page-style web applications with heavy DOM reconstruction (like FormulaTree), custom interactive elements such as search results, info-pills, and toggle headers are often implemented using non-semantic `<div>` or `<span>` tags. Without proactive ARIA attributes and focus management (`tabindex="0"`, `role="button"`, `role="option"`, and synchronization of `aria-expanded`), these elements are completely invisible and unusable for screen readers and keyboard-only users. Furthermore, keyboard interactions on custom components generate synthetic click events that lack standard pointer coordinates (`clientX` / `clientY`), requiring elements to fall back to `getBoundingClientRect()` to compute appropriate positioning for visual popups.
**Action:** Always assign explicit, semantic `role` attributes and `tabindex="0"` to any non-native interactive elements. Implement a centralized keydown event listener to map Enter and Space presses to programmatic `.click()` events, taking care to exclude native interactive controls (like buttons, links, and inputs) to prevent duplicate triggering. For custom popups, always use a bounding rect coordinate fallback to ensure proper placement during keyboard activation.
